## Project Context

This is a customer-facing web platform monorepo (Turborepo) with:
- **apps/web** — Next.js 14 customer dashboard
- **apps/api** — API service
- **packages/ui** — Shared component library
- **packages/db** — Prisma client and database access
- **packages/config** — Shared build configs

## Commands

- Install: `pnpm install`
- Build: `pnpm turbo build`
- Test: `pnpm turbo test`
- Lint: `pnpm turbo lint`
- Format: `pnpm prettier --write .`
- DB Migrate: `pnpm prisma migrate dev`

## Rules

### Code Style

Use TypeScript strict mode. No `any` types without explicit justification.
Use server components by default; add "use client" only for interactive elements.
Prefer named exports over default exports.
Use camelCase for variables, PascalCase for components, kebab-case for file names.
Limit functions to 40 lines. Extract helper functions when exceeded.

### Testing

Write unit tests using Vitest with describe/it blocks.
Co-locate test files: `component.test.tsx` next to `component.tsx`.
Write e2e tests in Playwright for critical user flows.
Mock external services using `vi.mock()`. Never call real APIs in unit tests.
Target 80% code coverage for new code.

### Git

Write commit messages in imperative mood: "Add feature" not "Added feature".
Keep commits atomic — one logical change per commit.
All changes require PR review before merge to main.

### Architecture

Respect monorepo package boundaries. Import via package names, not relative paths.
Shared UI components live in `packages/ui`.
Database access only through `packages/db` — never import Prisma directly in apps.
API routes validate all input with zod schemas at the boundary.

### Security

Never commit secrets, credentials, or API keys.
Validate all user input at API boundaries using zod schemas.
Use server actions for mutations; never expose internal database IDs to clients.
Sanitize all user-generated content before rendering.

### Database

Create Prisma migrations for all schema changes.
Never modify migration files after they've been applied.
Use transactions for multi-step database operations.

## Protected Paths (do not auto-modify)

- `prisma/migrations/`
- `.env*`
- `packages/config/`
